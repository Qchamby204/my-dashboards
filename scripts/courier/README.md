# Courier publication and playback

Courier remains at `courier.html`. Atlas links to this original dashboard.

## Publication

The weekday workflow has a first run and a backstop. A scheduled run generates an edition only when that date is absent from a structurally valid manifest. It then publishes audio, commits the manifest, requests a Pages build, and checks the public manifest and every advertised audio file. The backstop still performs the public checks when generation is skipped.

This explicit Pages request is necessary because [commits made with GITHUB_TOKEN do not trigger a Pages build](https://docs.github.com/en/actions/concepts/security/github_token). It uses the existing repository token with `pages: write` and the [Pages build endpoint](https://docs.github.com/en/rest/pages/pages#request-a-github-pages-build). It does not change the site's audience or publishing source. A run cannot report successful publication merely because its commit or build request succeeded.

Generation failures fail the run. Partial editions retain readable sections and report the audio/text-only counts in the workflow summary. Unavailable audio or a stale live manifest makes verification fail after bounded retries. No content is regenerated by those retries. GitHub can delay scheduled execution; this workflow does not promise an exact delivery time.

New audio URLs include their audio commit SHA, so a same-day rebuild cannot reuse a CDN URL for different bytes. Existing archive URLs remain intact. Publication runs are serialized. Manifest commits rebase onto current main so unrelated edits made during generation are preserved; conflicts fail visibly.

For delivery recovery, run **The Courier daily briefing** with **publish_only** selected. That republishes and checks the latest existing edition without model or voice calls. Leaving it unselected retains the manual rebuild behavior. Changes to the workflow or publication helper on main automatically perform the same publication-only check.

## Player

The original player uses one audio element across sections. Failed audio is reloaded when Play is retried. Continuation skips text-only sections, follows the saved preference, and reports a manual Play action if the browser blocks continuation. Play all explicitly starts the edition again; Resume listening continues an unfinished section in the selected edition.

Measured durations are kept with browser-local listening history and keyed by the actual audio URL. Queue time remains labelled approximate until every remaining audio length is known. Changing playback speed adjusts listening time remaining. No new account or sync service is involved.

[Media Session](https://developer.mozilla.org/en-US/docs/Web/API/Media_Session_API) supplies section metadata, playback state, elapsed position, play/pause, Next and seek actions when supported. Browser and iOS behavior varies; this is not a native Live Activity. Unsupported actions leave the page controls working normally.

## Verification

`node --test atlas/tests/courier-playback.test.mjs atlas/tests/courier-publication.test.mjs` exercises playback and publication with synthetic inputs. The publication test invokes the standard-library Python tests in `scripts/courier/tests`. These checks make no generation calls and send no notifications.

Physical iPhone checks remain necessary for lock-screen controls, Dynamic Island presentation, background continuation and installed home-screen behavior.
